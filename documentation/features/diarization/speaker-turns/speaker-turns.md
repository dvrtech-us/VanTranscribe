# Local speaker turns

`vt-diarize` derives speaker activity and changes from audio independently of speech recognition. It uses pinned pyannote segmentation-3.0 INT8 and 3D-Speaker ERes2Net embeddings through sherpa-onnx 2.0.1. No audio is uploaded. Ordinary diarization never creates or consults a cross-meeting voice gallery; separate explicit enrollment is governed by [voice memory](../../speakers/voice-memory/voice-memory.md). The clustering profile is explicitly experimental. Its thresholds were derived on 2026-11-10 by a rule fixed in advance from six public AMI calibration meetings and checked on seven speaker-disjoint held-out meetings ([trail](trail/2026-11-11-ami-derived-clustering-thresholds.md)); they are not validated for remote-call audio, and this increment does not satisfy the M2b accuracy/calibration acceptance gates.

## User flow

1. Explicitly request model setup after reading the model source/acquisition notice. Model setup never enables capture or accepts a publisher's gated account agreement.
2. Select remote or in-person processing. Remote microphone turns receive a channel-based `Me` prior; system audio is clustered separately. A saved different-person correction on the microphone overrides that prior and enables actual microphone embedding/clustering for the next pass. In-person microphone voices are clustered without a `Me` assumption.
3. Feed final recorded audio on a worker, or bounded live audio on a dedicated speaker worker. The result supplies independent timed turns rather than replacing immutable transcript text.
4. Map individual recognized words to the turn at each word's timestamp midpoint. A long STT final is never embedded as one speaker.
5. Review uncertain, provisional, short and overlap turns. Apply stored user identity corrections through time anchors. Missing or ambiguous anchors require review instead of transferring a name to an unrelated serial turn ID.

## Technical flow

`ModelManager` installs only on explicit request. It downloads two official HTTPS assets, limits redirects to GitHub's release hosts, checks exact byte counts and SHA-256, extracts only the exact regular segmentation model file without executing any archive script, and atomically renames a private staging directory after verification. Cancellation drops an inflight download, polled every 50 ms; network timeout is 180 seconds and connect timeout 10 seconds. A file lock rejects concurrent setup. Invalid existing packs require explicit removal before replacement. `installed()` is a cheap pinned-manifest/size check; inference construction verifies full model hashes. Pack identity (`models::verify`) is the manifest `id`, the two pinned weight hashes, the two notice files and the weight sizes (and, for the full check, weight SHA-256). The manifest's `embedding_version` and `calibration` fields are written at install time as a record of the clustering profile then current and are not compared, so a threshold change never makes an installed pack fail verification (which would otherwise strand it, because `install` refuses to replace a pack that fails verification). A pack installed before 2026-11-11 therefore keeps `calibration` "experimental_uncalibrated; assign=0.55 merge=0.70 margin=0.10; …" in its manifest while the code uses the current thresholds.

`Diarizer::accept` accepts at most two seconds of finite mono input at 8–192 kHz. Resampling, sample counters and clocks are separate per track. An explicit gap, sample-rate change, or timestamp discontinuity greater than 5 ms flushes that track's buffered context; its meeting-local speaker exemplars remain. No text or STT boundary enters the segmentation pipeline.

Source context depends on phase. `Phase::Live` preserves five seconds (80,000 real source frames at 16 kHz); `Phase::Refined` uses the canonical ten seconds (160,000 frames). Both retain a 2.5-second steady-state ownership stride. The pinned pyannote model expects ten seconds, so sherpa pads live windows and shorter terminal/gap tails. Full refined windows supply ten seconds of real source. Its one-window path returns local segmentation labels without global clustering, including simultaneous local speakers; timestamps remain clipped to actual source frames and the owned interval.

`Phase::segmentation_context()` returns a serializable `SegmentationContext { source_window_ms, ownership_stride_ms, native_window_ms }`: Live is `{5000,2500,10000}` and Refined is `{10000,2500,10000}`. **Source window is the configured maximum**, not a claim that every turn observed ten seconds of real context. On finish, gap or format change, a shorter remaining tail is native-padded and owns all its remaining actual frames; that terminal ownership can exceed the normal 2.5-second stride. No timestamp or source duration is invented for padding.

Per-track audio storage remains bounded: normal accepted input leaves less than one configured source window queued, with initial capacity of window plus 32,000 frames for the maximum two-second resampled packet (112,000 frames live, 192,000 refined). Source audio is never concatenated for a whole meeting. The larger refined context changes segmentation context only; live timing, short/Unknown/overlap handling, clustering thresholds (0.55 / 0.70 / 0.10 at that time; now 0.50 / 0.60 / 0.05), constraints and embedding persistence policy remain unchanged.

The public sherpa Rust diarizer does not expose raw segmentation matrices or embeddings. The implementation therefore obtains local turns from its single-window path and independently invokes `SpeakerEmbeddingExtractor` on clean turn audio. Segmentation and standalone embedding sessions each use one CPU thread and run sequentially on the speaker worker. The segmentation wrapper also constructs an internal extractor, so two copies of the embedding model can be resident.

An emitted turn shorter than 1,000 ms is `Unknown` and receives no speaker ID. No short turn inherits its predecessor. Overlapped intervals never update a clean speaker exemplar. If both local voices have clean owned turns in that window, their speaker links are retained and remapped after final clustering; otherwise the interval remains `Overlap` without an invented identity.

Clean turns use nearest-cluster cosine assignment only at or above 0.50 (`ASSIGN`) and a 0.05 second-best margin (`MARGIN`). Otherwise `Clusters::assign` either opens a new provisional cluster or, for an ambiguous window, leaves the turn unattributed. Best below 0.50, or no candidate, opens a cluster. When best is at least 0.50 but not ahead of the runner-up by 0.05 (a margin failure): if best is at least 0.60 (`MERGE`) no cluster is opened and the embedding is added to no cluster (no exemplar, member or speech time), `assign` returns `Ok(None)`, and the engine emits the turn with no speaker ids, no score, label `Unknown`, `uncertain = true`, `provisional = false`; the embedding record is kept, so the replay in `finish` decides again. If best is below 0.60 a new cluster opens. A turn that is a must-link or cannot-link endpoint always keeps the cluster-opening behaviour so saved corrections are not pushed into review. See the [ambiguous-voice trail entry](trail/2026-11-10-ambiguous-voice-stays-unattributed.md). The new cluster becomes visible only after the 3,000 ms rule below. A cluster becomes visible after 3,000 ms of owned speech. Up to 20 L2-normalized exemplars per cluster are retained, pruning the exemplar least similar to the mean. There are at most 64 clusters per track (`MAX_CLUSTERS`); what happens at the cap is described under *Cluster cap handling* below. Cosine scores are similarities, not identification probabilities. The thresholds (`ASSIGN` 0.50, `MERGE` 0.60, `MARGIN` 0.05 in `crates/vt-diarize/src/models.rs`) are tied to this exact embedding/preprocessing version. They come from a stated rule applied to a small public calibration set (six AMI in-person meetings, one room microphone) and were checked on seven held-out AMI meetings; they are not production-accepted and say nothing about remote-call audio. See the [threshold trail entry](trail/2026-11-11-ami-derived-clustering-thresholds.md). Until 2026-11-11 they were 0.55 / 0.70 / 0.10, unvalidated placeholders.

`finish` records `Some(config.phase.segmentation_context())` from the actual native engine, flushes both tracks, resolves persisted temporal constraints, replays up to 8,192 in-memory clean-turn embeddings with those constraints, and performs constrained agglomeration of bounded seed clusters at or above 0.60 (`MERGE`). A bounded exemplar-sample silhouette score with a soft live-count prior selects among that merge hierarchy. Must-links override acoustic similarity; cannot-links block assignments and merges. Transitive must-link components are computed before assignment, so a future endpoint cannot make an earlier greedy seed violate a known cannot-link. Conflicting constraint components become explicit pending reviews and Unknown regions instead of aborting transcript processing. This refinement can split a previous live seed when a supplied constraint requires it, but cannot automatically undo all mistaken unconstrained seed assignments. Global raw-embedding agglomeration and complete DER acceptance remain open.

Time anchors include track/start/end and resolve to the unique maximum-overlap non-overlap turn, requiring at least 50% anchor coverage. The standalone strict `resolve_temporal_constraints` utility returns `DiarizeError::Constraint` for unresolved anchors. The normal `Diarizer::finish` path evaluates constraints individually: missing, tied, under-covered, overlapping or unavailable embedding evidence becomes `ConstraintReview { provenance, reason, anchors }`. Conflicting resolved components are handled the same way. Every intersecting affected turn (and any correction connected to it) becomes Unknown with empty speaker IDs, `uncertain=true`, no score and `constraint-review` provenance. Those records are excluded from final clustering; valid corrections and baseline clustering outside the affected component continue. The full transcript and turn timing can therefore still be published alongside pending reviews. Model and native-audio failures remain hard errors. A turns, embeddings or clusters capacity limit is an error from `Diarizer` but no longer fails refinement; see the capacity paragraph below. A defensive replay failure carries its implicated turn IDs (or exact violated-pair endpoints), expands only their connected constraint component and retries after reviewing/masking that component. Retries are bounded by the initial candidate count plus one. Independent corrections on either track remain active and are not converted into failures.

When a valid relationship depends on an already-unknown endpoint, it is temporarily deferred under the **original failed source review**. That source review gains the dependent spans and explicit dependency wording; the valid neighbor's provenance is not emitted as a separate removable failure. Fixing or removing the original correction allows the dependent relationship to apply on a later refinement. A prior-only microphone must-link records explicit user confirmation of that channel relationship, not biometric recognition.

A remote microphone cannot-link present at construction switches that track from the Me channel prior to actual embedding/clustering. If such a correction is added only at finish, its earlier microphone audio has no stored embeddings: affected microphone regions become Unknown and a review asks for refinement again, while unaffected microphone regions retain the default Me prior. A fresh refinement receives the saved correction at construction and can compute the required voices. Unresolved live constraints also mask affected outgoing provisional labels until final replay.

`DiarizationResult.segmentation_context` is optional and serde-defaulted for compatibility. Legacy results without metadata remain `None`; callers must never infer ten-second context from an older run kind. Pure synthetic finalization also leaves it unknown. Session persistence copies existing context unchanged when annotations are retained without a new acoustic pass.

Serial turn IDs are run-local only. `set_temporal_constraints` allows the caller to supply a current anchor snapshot before finalization.

Bounds are 32,768 turn records per meeting, 8,192 clean embeddings, 64 clusters per track and 20 exemplars per cluster. Reaching the constraints, turns or embeddings cap is an explicit `DiarizeError::Capacity(CapacityLimit)` (`DiarizeError::capacity_limit()`), never silent truncation or a complete result. Reaching the per-track cluster cap is handled by merging, evicting or leaving speech Unknown (see *Cluster cap handling*); `Capacity(CapacityLimit::Clusters)` is returned only for a turn that is a must-link or cannot-link endpoint and cannot get a cluster. Any `accept` error poisons that instance and clears buffered audio/replay vectors; future calls require a new instance, so ignoring an error cannot grow its audio queue. Unnamed diarization embeddings exist only in memory and are cleared from replay storage after successful finalization. `DiarizationResult`, `SpeakerTurn` and model manifests contain no embeddings. Per-track speaker clusters have distinct namespaces, and the system track cannot receive the remote microphone `mic:me` prior.

**Cluster cap handling.** `Clusters::assign` calls `make_room` only when a window needs a new cluster (no required must-link cluster and no clear winner) and the track already holds `MAX_CLUSTERS` (64) clusters; below 64 it opens a cluster as before. At the cap, in this order (`crates/vt-diarize/src/cluster.rs`):

1. `cap_merge(false, MAX_CLUSTERS - CAP_HEADROOM)`: merge the most similar pairs with centroid cosine at least `MERGE` (0.60), highest first, considering only pairs in which at least one cluster is provisional (under `ESTABLISHED_MS` = 3,000 ms of speech) and that are not forbidden by a cannot-link, until at most 56 clusters remain (`CAP_HEADROOM` = 8 slots freed so the pass does not rerun on every following open) or no eligible pair is left. The cluster with more speech absorbs the other (the older one on a tie); ties between pairs keep the lowest indices, so replay is deterministic.
2. If still at 64: `cap_evict` removes the oldest cluster that has a single member, under 3,000 ms of speech and no constraint-anchored member (one slot). Its speech is counted in `cap_evicted_ms` and the window that created it becomes Unknown.
3. If still at 64: `cap_merge(true, MAX_CLUSTERS - 1)` merges the single most similar pair of two established clusters (cosine at least 0.60, not forbidden).
4. If any merge happened in steps 1 or 3, the window is re-scored; if it now has a clear winner (cosine at least `ASSIGN` 0.50 and at least `MARGIN` 0.05 ahead of the runner-up) it joins that cluster (`cap_reassigned`) instead of opening one.
5. If there is still no free slot: a window that is a constraint endpoint returns `DiarizeError::Capacity(CapacityLimit::Clusters)` and sets `capacity_refused`; any other window is left unattributed (`cap_unattributed`, `assign` returns `Ok(None)`) and is emitted Unknown and uncertain with no speaker id, as for an ambiguous window. Otherwise a new cluster opens.

Every merge is recorded through `record_merge` (into `forced_merges`, which `refine` starts its published history from, and into the `retired` map); an eviction is recorded in `retired` as `None`. After a window in which `retired` grew, `Diarizer` rewrites the clean turns it has just built in that window through `Clusters::resolve`: a merged id becomes its current id (visible label `Speaker N` when established, otherwise Unknown, uncertain and provisional), an evicted id becomes Unknown, uncertain, not provisional, with no speaker id or score, and the `mic:me` prior is untouched. Turns published by earlier windows keep their old id until the final result from `finish`, which replays the embeddings. When any track's diagnostics show `cap_reached()` (any of `cap_merges`, `cap_evictions`, `cap_unattributed` above zero; `cap_reassigned` alone does not count), `finish` appends `CAP_WARNING` to `DiarizationResult.warnings`: "Speaker separation reached its cluster limit; some similar voices were merged and some speech is shown as Unknown." The merge and evict rules are covered by synthetic tests in `crates/vt-diarize/src/tests.rs`, including a long four-voice call with word midpoints. **No replay measurement of this change on the real recordings is recorded in the repository** (the measurement copies were lost in a machine restart), and label quality on single-microphone in-person audio is unvalidated. See the [trail entry](trail/2026-11-10-cluster-cap-recovery.md).

**Refinement on a capacity limit.** In `speaker_pipeline::refine`, `separate` runs the audio pass and `Diarizer::finish`; `settle` then handles the outcome. If separation fails with turns, embeddings or clusters capacity (`recoverable_capacity`; clusters capacity now arises only for a constraint endpoint, see *Cluster cap handling*), refinement continues: the refined transcript is produced and published and the meeting becomes ready. Nothing from the failed attempt is saved. `store::retain_speakers_after_failed_separation` copies the previous run's speaker keys, timed turns, user overrides and pending reviews onto the new run (the same copy used when the speaker model is unavailable) and appends a warning to the run's speaker warnings, shown under Processing notes in the Speakers tab. `capacity_warning` builds it: "Speaker separation could not finish for this recording (limit: {limit}). The refined transcript is complete. " followed by "Speaker labels, names and corrections from the previous transcript were kept and applied by time." (previous turns exist), "Speakers are shown as Unknown." (none, in-person meeting) or "The transcript is labelled by channel (Me / Them)." (none, remote meeting). The constraints limit (raised by `Diarizer::new` when too many saved constraints are supplied), model errors, native-audio errors, invalid input and cancellation still fail the refinement. When the previous run is a live run, its labels may be fragmented or stop early, and the warning is not prominent in the UI.

**Diagnostics.** `Diarizer::diagnostics()` (`crates/vt-diarize/src/diagnostics.rs`) returns fixed-size counters and remains available after an error: windows, turns, embeddings, the limit that fired, the track and approximate input time when it fired, and per track the assignments to existing clusters, clusters opened by reason (no candidate, best score below the 0.50 assign threshold, margin failure, all candidates removed by cannot-link), peak and singleton cluster counts and score/margin histograms. Margin failures are also counted as `margin_failures`, `margin_failure_best_at_least_merge`, `margin_failure_centroid_hist` (cosine between the two top candidates' centroids) and `ambiguous_unattributed` (windows left unattributed). Cluster-cap handling adds `cap_merges`, `cap_evictions`, `cap_evicted_ms` (speech of evicted singletons), `cap_unattributed` and `cap_reassigned`, and `TrackDiagnostics::cap_reached()`. It stores no audio, embeddings or text and does not change clustering. The ignored test `crates/vt-session/src/real_call_replay_tests.rs` (`VT_REPLAY_ROOT` and `VT_REPLAY_MEETING`, which must point at a copy of an app data directory) prints only these counters. The first measurement is recorded in the [2026-11-10 trail entry](trail/2026-11-10-clustering-capacity-measurement.md).

**Measured limits of the margin rule.** On the 2026-11-09 remote call (system track) the rule removed the cluster cap: Refined 17 final speakers (3 confident), about 14% Unknown time; Live 31 speakers (7 confident), about 32% Unknown. Live labelling on that call is still implausible. On the 2026-11-10 95-minute in-person call (single room microphone, mic track clustered) the cluster cap was still reached (Refined at about 2617 s after 654 embeddings, Live at about 902 s after 270); at that time the cap was a `Capacity(Clusters)` error. Since commit 4fdc69b the cap is handled as described under *Cluster cap handling* and this measurement was not repeated, so that behaviour has not been measured on this call. These two measurements used the thresholds of their time (0.55 / 0.70 / 0.10) and were not repeated with the current ones. The embedder is still the zh-cn ERes2Net. Since 2026-11-11 there is also a public AMI evaluation (in-person meetings only), see the [threshold trail entry](trail/2026-11-11-ami-derived-clustering-thresholds.md); there is still no measurement on remote-call audio with the current thresholds.

**Live speaker saves.** `LivePublisher` (`speaker_pipeline.rs`) saves live turns through `store::save_live_diarization_with` -> `speaker_store::save_live_updates_with`. The save uses an IMMEDIATE transaction on a fresh connection and retries when `store::sqlite_busy` reports busy/locked (`LiveSaveBudget::PRODUCTION`: 3 attempts, 300 ms busy timeout each, 50 ms then 100 ms backoff, 1.05 s worst case; shortened on 2026-11-10 from 1.5 s / 100-200 ms / 4.8 s so a live save never queues for seconds ahead of the recorder's chunk writer, see the [live transcript persistence trail entry](../../transcription/live-english/trail/2026-11-10-live-transcript-persistence.md)). If the save still fails with a lock, the worker stays alive, adds the health warning "Live speaker labels could not be saved yet; they are kept and retried with the next update. Raw audio is preserved. Cause: <error> (SQLite extended code <n> <NAME>)" and keeps the unsaved turns (at most `MAX_PENDING_LIVE_TURNS` = 2048) for the next successful save. Turns dropped on overflow, or still unsaved when the publisher is dropped without the final reconciled save superseding them, are recorded as inference gaps with reason `persistence_failed`. Engine errors and non-lock database errors remain fatal (`worker_failed`) and a failed worker is not restarted. A fatal failure also adds "Live inference worker <thread-name> stopped: <error>[ (SQLite extended code <n> <NAME>)]" (`session::worker_failure_warning`, cause capped at 300 characters). The other deferred read-then-write transactions in `vt-session`, including the reconciled save at finish and the refine-time saves, are unchanged and not retried. See the [2026-11-10 live save trail entry](trail/2026-11-10-live-speaker-save-lock-contention.md).

Its original [pyannote model card](https://huggingface.co/pyannote/segmentation-3.0) is marked MIT and describes a gated Hugging Face acquisition process. This application downloads the [public official sherpa release](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/models.html) only on request and never logs into or accepts conditions on that original repository.

The original [ERes2Net ModelScope card](https://modelscope.cn/models/iic/speech_eres2net_base_sv_zh-cn_3dspeaker_16k) explicitly declares Apache License 2.0; the [3D-Speaker project license](https://github.com/modelscope/3D-Speaker/blob/main/LICENSE) is retained as well. The converted ONNX metadata identifies that exact original model, Chinese source language, 16 kHz, 512 output dimensions, normalized samples and global-mean feature normalization. The manifest records source URLs, authors/attribution, conversion, license evidence, acquisition notice and, as an install-time record that verification does not compare, the clustering profile (`calibration_profile()`: currently "experimental_ami_rule_v1; assign=0.50 merge=0.60 margin=0.05; derived from 6 public AMI in-person meetings by a fixed rule, checked on 7 held-out meetings; not validated for remote calls or production; NOT identification confidence"). Original weight revisions/conversion commits are not provided by those release assets; no revision is invented.

`EMBEDDING_VERSION` is SHA-256 over the pinned weights hash plus sherpa 2.0.1, mono 16 kHz, metadata preprocessing, post-L2 normalization and experimental calibration-v1/thresholds. It must change with any of those inputs; with the 2026-11-11 thresholds it is `ff29acb3…` (was `fb58e351…`). It identifies the clustering profile that produced a run (stored in `app_speaker_run_state.embedding_version`); it is not part of model-pack identity and not the voiceprint version. Because it changed, a run refined before 2026-11-11 no longer matches it, and "Remember voice" (`vt-session` `voice_memory.rs`) asks the user to refine again first; stored voiceprints are versioned by `voice_embedding_version()`, which does not include clustering thresholds, and are unaffected. No comparison with another model version is supported.

## Integration, storage and access

The session layer owns explicit user setup actions, model status/progress, background-worker scheduling, immutable processing-run publication, names/identity constraint persistence and UI warnings. User names should attach through temporal constraints and root reconciliation, not by preserving a serial cluster index across reruns. The crate creates no database tables and has no SQL artifacts or HTTP application routes. `VoiceEmbedder` in `crates/vt-diarize/src/voice_embedding.rs` verifies the same pinned model pack and recomputes one to five seconds of contiguous finite mono source audio for explicit enrollment. Each call has fresh 16 kHz resampling state and returns a normalized 512-dimensional vector only in memory. Its separate `voice_embedding_version()` hashes the pinned embedding weights, sherpa/preprocessing/resampling contract, individual f32 normalization, duration-weighted f64 mean normalization and explicitly unavailable identification calibration. It neither compares people nor writes vectors; the session validates consent, actual refined segmentation-context metadata (a Refine run name alone is insufficient), source eligibility and encryption before persistence. Persist only result metadata and explicit user constraints, never unnamed vectors. Model setup accesses official download hosts; inference performs no network access or permission request.

Full live/refined duration-overlap/Hungarian split/merge identity reconciliation, calibrated cross-meeting recognition, thresholds validated for remote-call channels and accepted for production, annotated DER/overlap scores, long-call CPU/memory/latency, overload/backpressure behavior and live five-second / refined ten-second segmentation quality remain independent acceptance work. Live labels must remain visibly provisional/experimental; a public smoke fixture is not a calibrated diarization benchmark.

## Validation

`cargo test -p vt-diarize` uses synthetic embeddings/time anchors and does not download models or read meeting audio. Ambiguity, drift and cap fixtures are expressed relative to `ASSIGN`/`MERGE`/`MARGIN` with asserted preconditions (`thresholds_leave_room_for_the_ambiguity_fixtures`, `drifted_pair`, `two_voice_call`), so a retune fails a stated precondition instead of silently changing what a test means. `models::manifest_tests` checks that a pack whose manifest carries the pre-2026-11-11 `embedding_version`/`calibration` strings still verifies and that other weight hashes are still rejected. It covers margin ambiguity on both sides of MERGE (unattributed above, new provisional cluster below), three-second provisional visibility, per-track isolation, capacity, must/cannot conflicts, constrained merges, silhouette selection, temporal rerun matching and word midpoint boundaries.

The opt-in real test uses only an explicitly supplied public fixture and verified model pack:

```sh
VT_DIARIZE_MODEL_DIR=/path/to/verified/pyannote3-eres2net-2024-v1 \
VT_DIARIZE_FIXTURE_WAV=/path/to/official/0-four-speakers-zh.wav \
cargo test -p vt-diarize real_public -- --ignored --nocapture --test-threads=1
```

That official four-speaker demonstration passed actual segmentation/embedding inference, multiple voice clusters, audio-derived clock bounds, short-turn Unknown behavior and remote microphone channel priors. The observed smoke result was 19 turns and six experimental clusters on a known four-speaker clip, demonstrating over-segmentation and the need for calibration; it did not establish DER or overlap accuracy. The fixture is downloaded to a temporary research cache only; its separate redistribution license is not established, so it is not bundled and is not the project's annotated English evaluation set. The real native regression also verifies that a constructor microphone cannot-link overrides the Me prior, a late correction produces Unknown/review instead of aborting, and an unmatched time anchor retains the full native turn count. No private user recording was used.

The phase-context regression uses a SHA-pinned public 6.625-second control through `VT_DIARIZE_CONTEXT_WAV`. Its small `src/fixtures/live5-public-control-baseline.json` was captured from the unchanged live five-second engine before this increment; it contains derived times/labels/flags, no audio or embedding vectors. The new native live test compares update/final geometry and policy fields against that baseline (floating scores are not golden values). The refined test verifies no emission before ten seconds, two owned prefixes, a longer terminal tail, short-turn Unknown policy, independent gaps/rate changes, sample bounds, bounded buffers and explicit provenance. Existing public multi-speaker, 48 kHz/gap and user-constraint tests remain separate regressions. The constraint test now feeds sixteen seconds rather than eight, so it still supplies at least two clean owned turns under ten-second source context; split/late/unmatched assertions are preserved.

The enrollment extractor has pure version/geometry regressions and an opt-in SHA-pinned public-control test for actual finite, normalized, repeatable output. A separate AppService test repeats that public control under a synthetic single-speaker turn assignment and exercises actual decoding/extraction plus encrypted persistence with a fake key provider. Both open no devices or OS secrets and establish integration, not speaker purity or identification accuracy.

`VoiceEmbeddingProfile` now also exposes a separately versioned English WeSpeaker ResNet34 research extractor through `VoiceEmbedder::new_with_profile`. This is used only by explicit developer calibration comparisons. Existing `VoiceEmbedder::new`, application enrollment and `Diarizer` still use the original ERes2Net pack and versions. No speaker-turn clustering profile, model preference or recognition availability changes. The [comparison checkpoint](../../../planning/Architecture/2026-11-07-english-speaker-calibration-comparison.md) records the research contract and evidence.

The additional `wespeaker-resnet34-cmn-v1` research identity restores required external feature mean subtraction through a deterministic ONNX metadata addition. It retains the original graph/parameters and uses a distinct derived-container pin, transformation marker and attribution; the ordinary WeSpeaker profile remains unchanged for reproducing its failed result. Both paths remain developer research choices, and the app continues to construct ERes2Net by default.

`wespeaker-resnet34-reference-frontend-v1` keeps those CMN bytes and changes only the research frontend to Hamming, snipped edges and an 8 kHz cutoff. `VoiceEmbedder::new_with_profile` rejects that profile. The calibration command constructs it from `crates/vt-speaker-frontend` after the pack is verified. Application enrollment and diarization still use ERes2Net.
