# Consented encrypted speaker memory

Date: 2026-11-07. Continues the full accepted [design](../../../design.md) and [meeting-detection checkpoint](2026-11-07-meeting-detection-validation.md). The accepted Anthropic and Codex design reviews remain the implementation basis. The original M0–M5 scope stays active.

## Implemented boundary

Speaker memory starts off and no ordinary inference run saves an unnamed embedding. Enabling requires a separate biometric explanation. An explicit enrollment requires a named person, written-consent attestation or own consent, its method and operator, the active completed refined run, retained source audio and at least twenty seconds of clean single-speaker non-overlapped refined speech. Shared rooms, provisional/uncertain sources and incompatible channels cannot enroll. This remains experimental source selection; it does not prove calibrated diarization or identity.

The native model recomputes bounded one-to-five-second windows from verified retained source audio into memory, capped at 120 seconds selected clean speech. Gaps, epochs, clipping and source frame geometry bound each span. No decoded plaintext temporary audio is written. Version identity hashes pinned embedding weights, preprocessing, native version, normalization and the explicitly unavailable calibration version. Remote channel classification is an explicit user declaration because a high-rate system tap does not reveal an upstream phone/meeting codec; room microphone classification derives from in-person mode.

The separate `vt-speakers` store encrypts named biometric vectors before SQLite insertion, using RustCrypto XChaCha20Poly1305 with random 24-byte nonces and authenticated row/person/channel/provenance/version metadata. Its random 32-byte key is stored under a separate, canonical-data-root-scoped macOS Keychain account. Add-only key creation does not replace an unreadable existing key; an authenticated key-check sentinel prevents silently accepting a different key for existing records. Metadata/status/settings/deletion/expiry do not query Keychain. Missing, locked, wrong or tampered key/ciphertext fails closed. Explicit Delete all clears the old verifier only after all protected biometric records are removed, permitting empty-store recovery.

A runtime reservation excludes capture and competing jobs while saved audio is read. Keychain access and inference run outside runtime/controller/SQLite write locks. The final transaction revalidates source/speaker/run/settings and the page's pinned generation before atomically saving the person, consent, encrypted exemplar and meeting link. Turning memory off can invalidate an in-flight enrollment. Old queued WebView enabling/enrollment requests cannot borrow a later generation.

Settings → People lists metadata, supports an editable copy-only consent request and requires confirmation before Forget/Delete all. Per-channel/version exemplar sets cap at ten with oldest-first eviction. Default expiry is twelve calendar months from a confirmed sample/match, configurable one through twenty-four. Startup, metadata access and hourly idle maintenance remove expired blobs even with memory off; person/consent metadata stays until explicitly forgotten. Forgetting clears links and biometric/attestation records in one transaction. Optional linked name removal clears overlays and invalidates derived search/summaries while retaining spoken content, personal notes, stored summaries, immutable history and exports. [PRIVACY.md](../../../PRIVACY.md) publishes the schedule and these limits.

## Explicit remaining requirements

Automatic recognition and suggestions are unavailable until version-specific gallery-aware calibration has been validated. This increment does not claim the M4 gallery-of-fifty recognition/false-identification targets, independent-meeting or same-person/channel quality, own-voice onboarding, automatic named match learning or stale-print recomputation, full database/audio encryption, Windows key storage or physical OS Keychain acceptance. Full M0–M5 and hardware/long-call acceptance remain open.

Primary cryptographic implementation reference: [RustCrypto chacha20poly1305 0.10.1](https://docs.rs/chacha20poly1305/0.10.1/chacha20poly1305/). This describes the primitive, not an audit of this app.

## Review notes retained

Forget/Delete all deliberately reduce biometric data without a page generation; enabling and enrollment remain fenced. A shared-room flag blocks future samples but does not retroactively remove existing saved prints or names; Forget is the explicit removal. Status currently assumes an active consent for each person because this app has no revoke-without-delete writer; a future revocation API must handle missing consent without disabling People/deletion. Meeting mode is immutable after recording, and future mode editing would require derived track/channel in the enrollment fingerprint. A native CFData key copy is released by the OS binding but cannot be zeroized through that safe API; no complete process-memory erasure is claimed. Forget is idempotent, the UI consent-method limit is stricter than the server limit, and a trusted store enrollment may update a person’s display name while the current UI preserves an existing selected name.

Native OS acceptance advances in the [Keychain checkpoint](2026-11-07-private-keychain-validation.md): the production provider passes a signed temporary-key roundtrip and second-process read, with exact cleanup and unchanged default/search-list settings. Locked-Keychain and installed-bundle upgrade ACL behavior remain open. Research matching/calibration continues in the [speaker matching checkpoint](2026-11-07-speaker-matching-calibration-validation.md).
